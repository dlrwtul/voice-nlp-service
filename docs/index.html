Voice NLP Service
A generic, schema-driven microservice that converts audio to structured JSON.
Send any audio file + a field schema, get back typed, normalized data.
v1.0.0

Built on OpenAI Whisper for multilingual transcription and Ollama / llama3.2:3b for intent extraction. One service, infinite use cases — the schema travels with each request.

How it works

🎤
1. Transcribe
Whisper converts audio to text — 99 languages, auto-detected.
→ /v1/transcribe
🧠
2. Extract
llama3.2:3b maps the text to your JSON schema with zero config.
→ /v1/extract
⚡
3. Full pipeline
One call, audio in, structured JSON out. Ready to feed your API.
→ /v1/voice-to-json

Use cases

The service is fully agnostic — you define what to extract. The same deployment serves all your apps:

  • Transport app — extract departure city, destination, date, passenger count
  • E-commerce — extract product name, quantity, color, size from voice orders
  • HR platform — parse leave request type, start date, end date
  • Food delivery — extract dish name, quantity, customizations, delivery address
  • Any app — define a schema, call the endpoint, done

Design principles

  • Schema-as-payload — no app registration, no server-side config per client
  • Stateless — every request is self-contained
  • Pluggable — swap Whisper model size or Ollama model via env vars
  • CPU-friendly — runs without GPU on small Whisper + llama3.2:3b
  • Optional auth — API key middleware, disabled by default

Quickstart

From zero to a working voice-to-JSON call in under 5 minutes.

1
Clone & configure
bash
cd services/voice-nlp
cp .env.example .env
2
Start containers
bash
docker-compose up -d
3
Pull the LLM (one-time, ~2 GB)
bash
docker exec -it voice-nlp-ollama-1 ollama pull llama3.2:3b
4
Make your first call

Test the text extraction endpoint (no audio file needed):

bash
curl -X POST http://localhost:8100/v1/extract \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Je veux aller à Ziguinchor depuis Dakar demain matin",
    "today": "2026-05-04",
    "schema": {
      "context": "Transport app in Senegal",
      "fields": [
        {"name": "origin_city",      "type": "string",  "description": "Departure city",   "required": true},
        {"name": "destination_city", "type": "string",  "description": "Arrival city",     "required": true},
        {"name": "date",             "type": "date",    "description": "Travel date",       "required": false}
      ]
    }
  }'

Expected response:

json
{
  "extracted": {
    "origin_city":      "Dakar",
    "destination_city": "Ziguinchor",
    "date":             "2026-05-05"
  },
  "missing_fields": [],
  "confidence": 0.95,
  "raw_text": "Je veux aller à Ziguinchor depuis Dakar demain matin"
}
5
Explore the interactive docs

Open http://localhost:8100/docs for the live Swagger UI.

Extraction Schema

The schema is the core abstraction that makes the service generic. You pass it with every request — no server-side registration required.

Schema shape

typescript
interface ExtractionSchema {
  context:  string          // What this app does — shapes LLM behavior
  fields:   SchemaField[]   // Fields to extract
  hints?:   string[]        // Domain hints (city names, product catalog…)
}

interface SchemaField {
  name:         string
  type:         "string" | "integer" | "float" | "boolean" | "date" | "datetime" | "enum"
  description:  string      // Sent to the LLM — be precise
  required:     boolean     // Missing required fields appear in missing_fields[]
  enum_values?: string[]   // Only when type === "enum"
}

Field types

TypeOutput formatExample inputExample output
stringAny string"Dakar""Dakar"
integerWhole number"two passengers"2
floatDecimal number"one and a half kilos"1.5
booleantrue / false"with air conditioning"true
dateYYYY-MM-DD"tomorrow", "next Friday", "le 5 mai""2026-05-05"
datetimeISO 8601"tomorrow at 8am""2026-05-05T08:00:00"
enumOne of enum_values"by bus""bus"

Using hints effectively

Hints are injected into the system prompt verbatim. Use them to help the LLM recognize domain-specific terms it might not know:

json
{
  "hints": [
    "Senegalese cities: Dakar, Thiès, Ziguinchor, Saint-Louis, Kaolack, Touba, Mbour, Tambacounda, Kolda",
    "'sept-place' is a shared taxi service (7-seat sedan)",
    "'car rapide' is a local minibus"
  ]
}
💡
Tip: The context field is the single most impactful parameter. A specific context like "Senegalese intercity bus booking app" yields far better results than a generic one like "transport app".

Pipeline

Understanding the two-stage process helps you choose the right endpoint and handle ambiguity correctly.

Stages

text
Audio file (.wav / .mp3 / .ogg / .m4a)
    │
    ▼  [Stage 1 — Whisper ASR]
    │  Model: configurable (tiny → large-v3)
    │  Auto-detects language
    │  Output: raw transcription text + language code
    │
    ▼  [Stage 2 — Ollama llama3.2:3b]
    │  Reads your ExtractionSchema
    │  Resolves relative dates using today param
    │  Output: typed JSON + missing_fields[] + confidence
    │
    ▼  PipelineResponse
       { transcription: {...}, extraction: {...} }

Handling missing fields

When a required field is absent from the audio, missing_fields lists its name. Your app should prompt the user to re-record with a targeted question:

php — Laravel example
if (!empty($response['extraction']['missing_fields'])) {
    return response()->json([
        'status'         => 'needs_clarification',
        'missing_fields' => $response['extraction']['missing_fields'],
    ], 422);
}
💡
Confidence threshold: Reject extractions below 0.6 confidence and ask the user to repeat. Values above 0.85 are generally reliable for structured fields.

POST /v1/voice-to-json Audio + schema → structured JSON

The full pipeline in a single call. Transcribes the audio with Whisper then extracts structured data with Ollama. This is the primary endpoint for client apps.

Request

Content-Type: multipart/form-data

FieldTypeRequiredDescription
audioFilerequiredAudio file
schemastring (JSON)requiredJSON-encoded ExtractionSchema
todaystringoptionalISO date for relative date resolution
⚠️
The schema field is a JSON-encoded string (not a nested object) because the request uses multipart/form-data. Serialize your schema with JSON.stringify() or json_encode() before sending.

cURL example

bash
curl -X POST http://localhost:8100/v1/voice-to-json \
  -F "audio=@recording.wav" \
  -F 'schema={"context":"Transport app","fields":[{"name":"origin_city","type":"string","description":"Departure city","required":true},{"name":"destination_city","type":"string","description":"Arrival city","required":true},{"name":"date","type":"date","description":"Travel date","required":false}]}' \
  -F "today=2026-05-04"

Response 200

json
{
  "transcription": {
    "text":             "Je veux aller à Ziguinchor depuis Dakar demain matin",
    "language":         "fr",
    "duration_seconds": 4.2
  },
  "extraction": {
    "extracted": {
      "origin_city":      "Dakar",
      "destination_city": "Ziguinchor",
      "date":             "2026-05-05"
    },
    "missing_fields": [],
    "confidence": 0.94,
    "raw_text": "Je veux aller à Ziguinchor depuis Dakar demain matin"
  }
}

Example — Transport (Faypass)

Searching for intercity bus trips by voice in French and Wolof.

Schema

json
{
  "context": "Senegalese intercity transport booking app",
  "fields": [
    { "name": "origin_city",      "type": "string",  "description": "Departure city",    "required": true },
    { "name": "destination_city", "type": "string",  "description": "Arrival city",      "required": true },
    { "name": "date",             "type": "date",    "description": "Travel date",       "required": false },
    { "name": "passenger_count",  "type": "integer", "description": "Number of seats",   "required": false },
    { "name": "service_type",     "type": "enum",   "description": "Vehicle type",      "required": false,
      "enum_values": ["bus", "minibus", "sept-place"] }
  ],
  "hints": [
    "Senegalese cities: Dakar, Thiès, Ziguinchor, Saint-Louis, Kaolack, Touba, Mbour, Tambacounda, Kolda, Diourbel",
    "'sept-place' is a shared 7-seat sedan taxi"
  ]
}

Test inputs

Input textExpected output
"Je veux aller à Ziguinchor depuis Dakar demain matin pour deux personnes"origin_city: "Dakar", destination_city: "Ziguinchor", date: tomorrow, passenger_count: 2
"Dakar Thiès yoon bi tey" (Wolof: Dakar Thiès trip today)origin_city: "Dakar", destination_city: "Thiès", date: today

Laravel integration

php — VoiceSearchController.php
public function search(Request $request): JsonResponse
{
    $schema = [
        'context' => 'Senegalese intercity transport booking app',
        'fields'  => [
            ['name' => 'origin_city',      'type' => 'string',  'description' => 'Departure city',   'required' => true],
            ['name' => 'destination_city', 'type' => 'string',  'description' => 'Arrival city',     'required' => true],
            ['name' => 'date',             'type' => 'date',    'description' => 'Travel date',      'required' => false],
        ],
        'hints' => ['Senegalese cities: Dakar, Thiès, Ziguinchor, Saint-Louis, Kaolack'],
    ];

    $nlp = Http::post(config('services.voice_nlp.url') . '/v1/extract', [
        'text'  => $request->input('text'),
        'today' => now()->toDateString(),
        'schema' => $schema,
    ]);

    $intent = $nlp->json();

    if (!empty($intent['missing_fields'])) {
        return response()->json([
            'status'         => 'needs_clarification',
            'missing_fields' => $intent['missing_fields'],
        ], 422);
    }

    return $this->tripRepository->publicSearchQuery(
        originCity:      $intent['extracted']['origin_city'],
        destinationCity: $intent['extracted']['destination_city'],
        date:            $intent['extracted']['date'],
    );
}

Environment Configuration

All settings are controlled via environment variables or a .env file in the service root.

env — .env.example
WHISPER_MODEL=small
WHISPER_DEVICE=cpu
OLLAMA_BASE_URL=http://ollama:11434
OLLAMA_MODEL=llama3.2:3b
OLLAMA_TIMEOUT=30
API_KEYS=
MAX_AUDIO_DURATION_SECONDS=120
LOG_LEVEL=INFO
VariableDefaultDescription
WHISPER_MODELsmallWhisper model size: tiny (fast) → large-v3 (accurate). small is the recommended balance for CPU.
WHISPER_DEVICEcpuSet to cuda to use an NVIDIA GPU. Requires nvidia-docker runtime.
OLLAMA_BASE_URLhttp://ollama:11434Ollama server URL. Use http://localhost:11434 for local dev without Docker.
OLLAMA_MODELllama3.2:3bOllama model to use for extraction. Upgrade to mistral:7b for better accuracy.
OLLAMA_TIMEOUT30HTTP timeout (seconds) for Ollama requests.
API_KEYSemptyComma-separated list of valid API keys. Empty = no authentication.
MAX_AUDIO_DURATION_SECONDS120Maximum audio file duration accepted.
LOG_LEVELINFODEBUG | INFO | WARNING | ERROR

Enabling API key authentication

env
API_KEYS=my-faypass-key-abc123,my-ecommerce-key-xyz789

Clients must send the key in the X-API-Key header:

bash
curl -H "X-API-Key: my-faypass-key-abc123" http://localhost:8100/v1/extract ...

Deployment

The service is designed to run as a persistent container alongside your existing stack.

Adding to an existing Compose stack

yaml
# In your main docker-compose.yml
services:
  voice-nlp:
    image: voice-nlp:latest   # build from services/voice-nlp/
    ports:
      - "8100:8000"
    environment:
      - OLLAMA_BASE_URL=http://ollama:11434
      - WHISPER_MODEL=small
    depends_on:
      - ollama

  ollama:
    image: ollama/ollama:latest
    volumes:
      - ollama-data:/root/.ollama

Docker healthcheck

yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
  interval: 30s
  timeout: 10s
  retries: 3

GPU support

yaml
services:
  voice-nlp:
    environment:
      - WHISPER_DEVICE=cuda
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
💡
Model warm-up: Whisper loads at startup (@app.on_event("startup")), so the first request after deploy doesn't pay the model load penalty. Ollama models load on first inference — expect a ~3s cold start on the first extraction call after Ollama restarts.
